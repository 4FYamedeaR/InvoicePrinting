# 许可资料核验工具

本目录提供项目许可资料的本地一致性核验工具。需要 Python 3.9 或更高版本，仅使用 Python 标准库，无需安装额外依赖。

在项目根目录运行：

```powershell
python tools/licensing/verify-licenses.py
```

脚本只读检查许可原文、中文译文、来源清单和相关项目文档，不修改这些文件，也不联网下载资料。它会创建报告目录，并写入核验报告：

```text
artifacts/license-checks/license-verification.json
```

每次运行都会覆盖该报告。报告也会输出到终端；核验通过时退出码为 `0`，发现不一致时为 `1`。

需要同时核对发布目录中的随附许可资料时，先生成发布成果，再运行：

```powershell
python tools/licensing/verify-licenses.py --published
```

`--published` 会额外检查 `artifacts/single-file/` 中的许可资料是否与项目中的对应文件逐字节一致，不会修改发布目录。

## 核验内容

- 对照历史原文基线，检查许可原文的 SHA-256。
- 核对各 `sources.json` 登记的文件是否存在、哈希及文件长度是否一致。
- 检查中文译文登记、对应原文、中文内容及乱码替代字符。
- 检查相关 Markdown 文档中的本地链接及必要的 FreeType、Independent JPEG Group 署名。
- 使用 `--published` 时，额外核对随发布成果分发的许可文件。

这些检查用于发现资料缺失、改动或发布副本不同步，不代表已经验证所有翻译的法律含义、完整的二进制组件清单或实际源码提交。

## 历史原文基线

`original-license-hashes.json` 保存本项目先前取得的上游许可原文校验值，用于确认整理及翻译过程中没有改变这些原文。基线记录的文件范围以该 JSON 为准；其他已登记资料仍由各组件的 `sources.json` 核验。

升级依赖或补充资料时，应先核实实际采用的组件、版本及上游来源，再明确更新相应来源清单、许可原文和必要译文。若历史原文确实随升级发生变化，应审阅并说明变化原因，随后明确更新基线；不要仅为消除核验错误而替换校验值。完成更新后，重新运行核验，并在发布后追加 `--published` 检查。

本目录不包含一次性的资料下载、生成或翻译脚本。
